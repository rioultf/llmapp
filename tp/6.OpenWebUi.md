`OpenWebUI` (ou `OWI` par la suite) est une interface qui permet de piloter :

* des utilisateurs et leurs droits sur les modèles
* des modèles, locaux par `ollama` ou par API
* mise à disposition d'outils / pipelines
* ce qu'il faut pour les campagnes d'annotation (*red teaming*)
* contrôle local sur les données
* serveur de `chat_completions` avec outil
* classement des modèles par ELO

C'est un logiciel du niveau d'une organisation importante et structurée, avec des administrateurs et des utilisateurs : il est donc très complexe et paramétrable.

Il est particulièrement bien conçu pour favoriser l'évaluation d'un modèle et ses paramètres et rationnaliser les interactions. L'interface de base n'a rien à envier à `chatGPT`. Elle améliore la gestion des threads.

# Démarrage 

```bash
docker image pull ghcr.io/open-webui/open-webui:latest

docker run -d -p 8080:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data --env GLOBAL_LOG_LEVEL="DEBUG" --name open-webui --restart always ghcr.io/open-webui/open-webui:latest

# commande complète avec pont Ollama
docker run -d -p 8080:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data -e OLLAMA_BASE_URL=http://host.docker.internal:11434 --env GLOBAL_LOG_LEVEL="DEBUG" --name open-webui --restart always ghcr.io/open-webui/open-webui:latest
```

Une interface web est disponible sur le port 8080.

C'est une interface client/serveur classique, n'oubliez pas de valider les formulaires !

# TP

## Administration de `OWI`

Il ne faut pas hésiter à s'y reprendre plusieurs fois.

* lancer le container `docker`
* [dans les réglages de l'admistration](http://127.0.0.1:8080/admin/settings/connections), ajouter une connexion (endpoint) compatible API OpenAI
  * <https://openrouter.ai/api/v1> (le survol de l'URL indique où va taper `OWI`)
  * API key
  * desactiver `ollama`

* piloter les modèles disponibles sur votre endpoint (la liste peut être longue si vous êtes chez `OpenRouter`) et par modèle :
  * réglages par défaut : stream / **[appel de fonction (natif ou par défaut)]** / seed / température : pléthore de réglages, certains spécifiques à `ollama`
  * system prompt
  * capacités : vision, upload, web, ... et built-in tools

  ## Espace de travail

  * définition d'un modèle accessible aux utilisateurs
  * modèle de base autorisé par l'administrateur
  * expérimenter l'arbre des interactions : il est possible de corriger les interactions pour brancher, puis de naviguer dans les versions
  * découvrir les icônes sous la réponse de la machine
