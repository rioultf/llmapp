Coder avec un LLM peut se faire directement dans le chat d'un grand model, à la main. C'est peut être possible lorsqu'il y a de légères modifications à faire à chaque fois ou pour guider des modifications, mais montre rapidement ses limites lorsqu'il s'agit de faire de nombreuses modifications.

Sans aller bien loin en termes d'interface, j'ai choisi de tester `aider`, qui valorise un LLM, de préférence distillé pour cela, en intervenant directement sur le code.

Il existe des alternatives intégrées dans des interfaces mias j'ai préféré rester au niveau bas.

Le codage assisté par LLM permet de d'interagir avec le LLM sur la base de code et de demander des modifications ciblées. Cela peut grandement améliorer la productivité mais requiert d'adapter les habitudes de développement edit/test. Il faudra s'habituer à boucler entre instruction/test/undo et limiter fortement le modifications manuelles, jusqu'à demander la correction d'une coquille. De petites tâches impliquant peu de modifications, on finit par lire le code par le biais des interactions avec le LLM.

Au niveau tarif, il faut compter `2$` par jour sur un modèle récent comme `gtp5-codex`, plus abordable que `sonnet4`. C'est un budget, et on comprend mieux pourquoi `Anthropic` propose des abonnements mensuels à `240$`.

J'ai expérimenté les modèles libres d'`OpenRouter`, mais ils ne sont pas suffisants.

*La mise au point de tests automatiques me semble essentielle mais je n'y connais pas grand-chose.*

# Paramétrage du `chat`

* pour insérer un retour à la ligne : `Alt-Enter`
* il y a un `/multiline-mode` (le prompt passe à `multi>`) :

  * pour valider une demande d'interaction avec le modèle : `Alt-Enter`
  * pour passer à la ligne dans le chat : `Enter`

ou :

        $ aider --multiline --model openrouter/openai/gpt-5-codex



Le chat d'`aider` fonctione selon différents modes :

```
\chat-mode

- help               : Get help about using aider (usage, config, troubleshoot).
- ask                : Ask questions about your code without making any changes.
- code               : Ask for changes to your code (using the best edit format).
- architect          : Work with an architect model to design code changes, and an editor to make them.
- context            : Automatically identify which files will need to be edited.
```

On passe d'un mode à l'autre par `/help`, `/ask`, `/code`, etc. `/code` réinitialise le prompt.

Le modèle utilise un *format* pour expliciter ses modifications, ce n'est pas optionnel. L'information est disponible en tapant `/code`.

`/help` install `torch`...

| Format                         | Meilleur pour…                        | Notes                                    |
| ------------------------------ | ------------------------------------- | ---------------------------------------- |
| **whole**                      | Refactorings larges                   | Simple mais lourd                        |
| **diff**                       | Changements ciblés                    | Économise des tokens                     |
| **diff-fenced**                | Diff ciblés avec compatibilité modèle | Très bon avec Gemini                     |
| **udiff**                      | Changements lisibles                  | Format standard largement compris        |
| **editor-diff / editor-whole** | Travail réfléchi via architect        | Deux étapes IA → changement plus robuste |

**Aider is configured to use the optimal format for most popular, common models. You can always force use of a specific edit format with the --edit-format switch.** -> c'est mieux de ne pas chercher à y toucher.

## Important

* une *commande* transmise à `aider` commence par `\` :

```
    /ls
    /add <fichier>
    /undo
    /
```

* une *requête* transmise à `aider` consiste en du texte **qui ne commence pas par `\`**. `aider` interprète la requête pour la transformer en interrogation du modèle, interprète la réponse et génère des actions : modification de fichier par 

```
<<<<<<< SEARCH
...
<code à rechercher>
...
=======
...
<code à remplacer>
...
>>>>>>> REPLACE
```

* lorsque `aider` modifie les fichiers, il génère également un *commit*.

## Conseils

* Il faut constamment vérifier quel est le contexte de la requête à l'API LLM

* Au démarrage d'une session de travail, aucun fichier n'est considéré dans le chat : le contexte est vide et `aider` ne peut que suggérer l'ajout de certains fichiers dans le chat, s'ils sont évoqués dans le prompt.

* On commence par lister les fichiers disponibles, *a priori* aucun n'est dans le chat.

    Repo files not in the chat:
    ...

* Ajouter les fichiers nécessaires à l'interaction avec `/add <fichier>`

* Utilise `/add` d’abord pour que l’IA sache quels fichiers éditer.
  * être en `/ask <requete>` pour planifier ou poser des questions sans modifications
  * vérifie fréquemment les changements via `/diff` avant de committer.
  * `/undo` si besoin
  
* Si on modifie les fichiers soi-même, mettre à jour le contexte par : 

        /drop <fichier>
        /add <fichier>

* `aider` peut scraper : "For the best web scraping, install Playwright"


## Commandes utiles

* /drop <fichier> — Retire un fichier de la session pour alléger le contexte.

* /read-only <fichier> — Ajoute un fichier en lecture seule (référence sans modification).

* /ls — Liste tous les fichiers connus et ceux inclus dans la session.

* /map — Affiche la cartographie du dépôt (utile dans les projets volumineux).

* /map-refresh — Rafraîchit cette cartographie.

# Commandes `aider`

## 🧠 Commandes principales pour coder avec `aider`

### 📁 Gestion des fichiers

* `/add <fichier>` — Ajoute un fichier à la session pour que l’IA puisse le lire ou l’éditer.
* `/drop <fichier>` — Retire un fichier de la session pour alléger le contexte.
* `/read-only <fichier>` — Ajoute un fichier en lecture seule (référence sans modification).
* `/ls` — Liste tous les fichiers connus et ceux inclus dans la session.
* `/map` — Affiche la cartographie du dépôt (utile dans les projets volumineux).
* `/map-refresh` — Rafraîchit cette cartographie.

📌 Ajouter uniquement les fichiers utiles aide l’IA à se concentrer et réduit la surcharge contextuelle. ([aider.chat][1])

---

### ⚙️ Contrôle des modes et modèles

* `/code` — Demande des modifications de code (par défaut).
* `/ask` — Pose des questions sans modifier le code.
* `/architect` — Active le mode *architect*, qui planifie de grandes modifications en deux modèles.
* `/chat-mode <mode>` — Bascule entre les modes (`code`, `ask`, `architect`, `help`).
* `/model <nom>` — Change le modèle LLM principal utilisé par aider.
* `/models` — Cherche/affiche les modèles disponibles.
* `/editor-model <nom>` — Change le modèle utilisé pour le rôle d’éditeur.
* `/weak-model <nom>` — Change le *weak model* (parfois utilisé pour commits et tâches auxiliaires). ([aider.chat][1])

---

### 💬 Navigation & édition

* `/clear` — Vide l’historique de la conversation.
* `/reset` — Supprime tous les fichiers de la session et nettoie l’historique.
* `/edit` (alias `/editor`) — Ouvre un éditeur pour écrire une requête complexe.
* `/context` — Montre le contexte autour d’un endroit précis du code.
* `/copy` — Copie le dernier message de l’assistant dans le presse-papier.
* `/copy-context` — Copie la session actuelle en markdown (pratique pour documentation/web). ([aider.chat][1])

---

### 📊 Visualisation des modifications

* `/diff` — Affiche les différences (diff) depuis le dernier message.
* `/run <commande>` — Exécute une commande shell et optionnellement injecte la sortie dans la conversation.

  * Exemple : `/run git diff HEAD~1` pour montrer un diff de commits. ([aider.chat][2])
* `/test <commande>` — Exécute une commande (ex : tests) puis ajoute la sortie seulement si elle échoue.
* `/tokens` — Indique le nombre de tokens utilisés dans la session.
* `/think-tokens <nombre>` — Définit le budget de réflexion (tokens) pour l’IA. ([aider.chat][1])

---

### 🧪 Git & commits

* `/commit [message]` — Commit les modifications en attente dans le dépôt (message facultatif).
* `/undo` — Annule le dernier commit si c’était fait par aider.
* `/git <commande git>` — Lance une commande Git (la sortie n’est pas incluse dans la conversation). ([aider.chat][1])

---

### 🛠️ Utilitaires et extras

* `/lint` — Vérifie et corrige le style ou erreurs des fichiers en chat (ou tous les fichiers si aucun n’est précisé).
* `/voice` — Enregistre et transcrit l’entrée vocale comme texte.
* `/paste <texte|image>` — Colle du texte ou une image depuis le presse-papier dans le chat, optionnellement avec nom.
* `/web <URL>` — Récupère une page web et l’ajoute convertie en Markdown.
* `/help [question]` — Affiche de l’aide (avec ou sans question spécifique).
* `/report` — Ouvre un issue GitHub pour signaler un bug ou problème.
* `/settings` — Affiche la configuration actuelle de aider.
* `/save <fichier>` — Enregistre les commandes pour reconstruire la session plus tard. ([aider.chat][1])

---

## 🧭 Recommandations rapides

🔹 Utilise `/add` d’abord pour que l’IA sache quels fichiers éditer. ([aider.chat][3])
🔹 Bascule en ask mode (`/ask`) pour planifier ou poser des questions sans modifications. ([aider.chat][4])
🔹 Vérifie fréquemment les changements via `/diff` avant de committer. ([aider.chat][1])
🔹 Si une modification ne te plaît pas, `/undo` est ton meilleur allié. ([aider.chat][1])

Avant de fermer une session importante, exporte les prompts ou fais une copie locale du fichier .aider.chat.history.md pour référence.

Lance aider avec --restore-chat-history pour avoir la discussion précédente sous la main en repartant du même repo.
